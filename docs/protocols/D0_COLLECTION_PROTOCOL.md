# WiFiTrustFusion D0 Collection Protocol

Protocol status: FREEZE CANDIDATE
Protocol identifier: PROTOCOL_V1_CANDIDATE

## Purpose

This protocol defines how WiFiTrustFusion acquisition sessions are prepared,
identified, collected, transferred, checked and handed over.

No D1 pilot collection is permitted until G1 explicitly freezes:

- COLLECTOR_V1
- PROTOCOL_V1
- OBS_SCHEMA_V1
- frozen APK or equivalent release artifact
- Git commit or release reference

## G1 Requirements

Before D1 collection begins, the following must be frozen:

- COLLECTOR_V1
- PROTOCOL_V1
- OBS_SCHEMA_V1
- frozen APK or equivalent release artifact
- Git commit or release reference

The data-acquisition operator must not modify collector code during an
active collection round.

## D1 Pilot Session Definition

A D1 pilot session is defined primarily by:

- 10 completed collector request cycles

The collector uses a 35-second post-completion interval between requested
scan cycles.

Expected elapsed duration is approximately 5.5 to 6 minutes, depending on
Android scan-completion timing.

The protocol does not require an exact five-minute wall-clock duration.

Actual timestamps, request-cycle counts and observation counts produced by
COLLECTOR_V1 remain authoritative.

## Session Identifier Authority

The canonical session_id is generated by COLLECTOR_V1.

The external session manifest must copy and use that exact collector-generated
session_id.

The Data Acquisition Track must not independently construct, replace or
reinterpret the session identifier.

Collector session-ID pattern:

DEVxx_YYYYMMDDTHHMMSSZ_XXXX

Fake example:

DEV01_20261011T130000Z_A1B2

The final XXXX component is collector-generated.

## External Session Manifest Linkage

The following controlled experimental-context fields remain in the external
session manifest:

- network_code
- location_code
- position_code
- orientation_code
- environment_condition
- scenario_id
- ground_truth
- operator_id
- operator_notes

These fields link to collector observations through the exact
collector-generated session_id.

They are protocol/session metadata and are not required to be duplicated in
every Wi-Fi observation row.

## Baseline Collection Procedure

For an N0 baseline session:

1. Confirm DEV01 and frozen G1 versions.
2. Confirm the authorized target network.
3. Record the exact collector-generated session_id in the external manifest.
4. Assign network_code, location_code, position_code and orientation_code.
5. Set environment_condition to NORMAL.
6. Set scenario_id to N0.
7. Set ground_truth to NORMAL.
8. Record operator_id.
9. Keep the device stationary at the defined position and orientation.
10. Complete 10 collector request cycles.
11. Expect approximately 5.5 to 6 minutes total duration.
12. Record operator_notes if relevant.
13. Preserve original collector output as RAW.
14. Run QC before assigning ACCEPTED or REJECTED.

## Normal Nuisance Variation Procedure

Normal nuisance conditions remain ground-truth NORMAL.

Initial scenario candidates:

N1 - Position variation
N2 - Orientation variation
N3 - Movement
N4 - Weak legitimate signal
N5 - Ordinary interference
N6 - Network congestion
N7 - Legitimate multi-BSSID behaviour

Change one intended nuisance factor at a time when practicable.

Do not label normal variation as malicious simply because measurements change.

## Device Position Rules

Each session has one defined position_code.

Baseline sessions keep DEV01 at that marked position for the complete session.

Movement is allowed only when the declared nuisance scenario requires it.

## Device Orientation Rules

Each session has one orientation_code.

Controlled values may include:

ORI_N
ORI_E
ORI_S
ORI_W
ORI_FIXED
ORI_VARIABLE

Baseline sessions use a fixed orientation throughout the session.

## Network and Environment Stability

For baseline collection:

- use only an authorized/team-controlled or explicitly permitted network
- do not intentionally change AP configuration during the session
- do not intentionally change security mode
- do not intentionally change captive-portal behaviour
- do not intentionally generate interference
- keep baseline position fixed
- keep baseline orientation fixed
- document unusual environmental changes in operator_notes

Normal environmental fluctuations are retained rather than manually removed.

## Restart and Repeat Rules

A failed session must not be silently overwritten.

If a session fails because of collector interruption, permission failure,
Wi-Fi/location availability, incorrect metadata, wrong scenario, version
mismatch, corrupted/missing output, insufficient usable collection or operator
error:

1. preserve the failed RAW session
2. record a rejection reason
3. mark it REJECTED when required
4. repeat using a new collector-generated session_id

Never reuse or manually construct the replacement session_id.

## Operator Notes

operator_notes should contain only relevant experimental information such as:

- unexpected movement
- people entering/leaving the environment
- temporary connectivity issues
- phone handling
- session interruption
- unusual network behaviour
- deviations from protocol

Do not place passwords or unnecessary personal identifiers in operator notes.

## Privacy and Sanitization

RAW acquisition data is stored outside Git.

Git-managed data must be sanitized.

Use pseudonymous identifiers such as:

DEVxx
NETxx
LOCxx
POSxx
OPxx

Do not commit:

- real ADB serial
- IMEI
- phone number
- Wi-Fi password
- personal SSID
- raw identifiable BSSID
- private network mappings

## DEV01 Compatibility Smoke-Test Pending Items

The following remain pending until the compatibility smoke test:

- Wi-Fi operational confirmation
- location-services confirmation
- APK installation confirmation
- Xiaomi/MIUI installation restrictions

Wi-Fi scan-throttling settings must not be changed during preparation or the

## D1 Pilot Size

Minimum planned D1 pilot:

3 N0 baseline sessions on DEV01.

D2/D3 scaling is prohibited until the D1 pilot has been reviewed and accepted.

## Core Data Integrity Rules

1. Never overwrite raw measurements.
2. Never manually edit measurements to improve results.
3. Preserve failed sessions.
4. Record rejection reasons.
5. Do not silently mix collector versions.
6. Do not silently mix schema versions.
7. Raw SSIDs and BSSIDs must not be committed to GitHub.
8. Every accepted session must be traceable through its canonical session_id.
9. Missing evidence must be reported as missing, not interpreted as safe.
10. Ambiguous observations must remain ambiguous.

## Ground Truth Principle

The operator records the controlled experimental condition.

The operator must not change labels because the measured data does not match
the expected hypothesis.

## Safety Boundary

Controlled abnormal scenarios must use only:

- team-owned equipment
- team-controlled networks
- explicitly authorized environments

No intrusive testing may be performed against third-party networks.

## Collection State Model

Every session has one logical state:

RAW
ACCEPTED
REJECTED

RAW: Original acquisition output.

ACCEPTED: Passed defined data-quality checks.

REJECTED: Retained but excluded from the accepted analysis dataset.

## Versioning

Protocol changes that alter acquisition procedure require a new protocol
version.

Collector changes that alter acquisition behaviour require a new collector
version.

Observation field changes require a new observation-schema version.
